# תהליך איכות להודעות סוכנים

## מטרת התהליך

מונעים הודעות ארוכות, קישורי פעולה חשופים ופרומפטים בקבצים. תיקון אינו נחשב הושלם לפי שינוי זיכרון בלבד.

## מחזור חובה

1. אפיון: שומרים את ההודעה הכושלת, הערוץ, סוג הפלט והסיבה הטכנית.
2. פיתוח: מתקנים את שכבת המסירה או את הזיכרון הפעיל. אין לעקוף תקלה בהודעה נוספת למשתמש.
3. בדיקות אוטומטיות: מריצים בדיקת יחידה, בדיקת טיפוסים ובנייה.
4. בדיקת מסירה: שולחים הודעת בדיקה אחת, קצרה וייחודית, רק לנתיב שנבדק.
5. אימות: בודקים סטטוס מסירה ואת התצוגה בערוץ. כשל מחזיר לשלב האפיון.

## תנאי קבלה

- פרומפט מופיע בהודעה אחת ובקופסת קוד. אין קובץ טקסט ללא בקשה מפורשת.
- פעולה מוכנה נשלחת ככרטיס קצר עם כפתור אחד. אין כתובת פעולה ארוכה בגוף הצ׳אט.
- קישור מידע רגיל נשאר קישור רגיל ואינו הופך לכרטיס.
- לכל הודעה רגילה יש כותרת מודגשת, בולטים קצרים ועברית קריאה.
- אין מקף ארוך, הודעות כפולות או הודעת מערכת גולמית למשתמש.
